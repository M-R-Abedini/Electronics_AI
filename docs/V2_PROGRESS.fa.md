### F0c · اثبات قرارداد ماکرو (2026-11-08، شاخهٔ `feat/v2-f0c`)

دو ماکرو از StickHub: **`usb_port_esd`** (J2 + D1 + D2، ماکروی واقعی ESD + کانکتور USB: ۱۶ ترک، ۳ via صفحه، port برای D+ و D-) و **`zone_test_vin`** (C21 + D24 + یک zone محلی VIN شبیه پولیگون SW). اجرا: `pixi run macro-proof <board> --refs ...`.

| گیت (پلن F0c) | نتیجه | آستانه | |
|---|---|---|---|
| ۱۶ وضعیت (۴ چرخش × ۲ سمت × مرکز/لبه) بدون خطای DRC | ۱۶ از ۱۶ برای **هر دو** ماکرو (۳۲ از ۳۲)؛ اتصال داخلی قطع‌نشده در همه | ۱۶ از ۱۶ | ✅ |
| مس خوانده‌شده = تبدیل محاسبه‌شده | پد، ترک، via و zone در هر ۳۲ وضعیت تا ۱ nm یکسان، از جمله ۱۶ وضعیت flip | تلورانس ۱ nm | ✅ |
| مس ماکرو بعد از Freerouting | ترک، via و zone محلی بیت‌به‌بیت یکسان (هر دو ماکرو روی StickHub، DRC از سهم router صفر) | یکسان | ✅ |
| پوشش با ماکرو ≥ بدون ماکرو | ماکروی واقعی USB: **۹۸٫۲٪** (۴ روت‌نشده) ≥ ۹۷٫۴٪ (۶) | ≥ | ✅ |

قواعد قرارداد (معماری ۴.۴) روی هر دو ماکرو: مس کامل (۰ سر آزاد)، هر via به پد خودش وصل، یک port برای هر نت خروجی، flip مجاز (نقش لایه‌های F و B یکسان). مسیر ESD→U1 عمداً بیرون از ماکرو ماند (قاعدهٔ ۵؛ مال S6a).

**رگرسیون:** SES روت StickHub بدون ماکرو بیت‌به‌بیت همان F0a (`b078884b…`)؛ رفت‌وبرگشت ۸ برد هنوز ۸ از ۸.

**یافته‌های این فاز که روی روت کل پروژه اثر دارند** (جزئیات و شاهد: دفتر تصمیم‌ها، ردیف‌های F0c):
1. Freerouting روی royalblue ۵۶ ترک سیگنال روی **صفحه‌های GND خالص** In1 و In3 کشیده بود (متخصص هیچ). اکنون لایه‌های plane خالص `power` صادر می‌شوند ⇐ صفر ترک روی آن‌ها.
2. Freerouting zone محلی را برای نت‌های دیگر مانع نمی‌بیند ⇐ `wire_keepout` روی zone ماکرو.
3. teardropهای کهنهٔ متخصص به خروجی روت‌شده برمی‌گشتند (royalblue: ۲۶۳) ⇐ رفع شد.
4. import SES کیکد مس قفل‌شده را پاک می‌کند ⇐ مس ثابت بعد از import برمی‌گردد.

گالری: `.runtime/f0c/gallery.html`. آزمون‌ها: ۲۱ واحد + ۹ کند، همه پاس؛ ruff تمیز.
