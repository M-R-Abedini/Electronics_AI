# ایرادها و معیار پذیرش V2

مرجع دامنه و ترتیب فازها [پلن V2 و اصلاحیهٔ ۵٫۱](V2_EXECUTION_PLAN.fa.md) است. بنچمارک‌ها و تصمیم‌های مهندسی در [دفتر تصمیم‌ها](V2_DECISION_LOG.fa.md) ثبت می‌شوند.

| مورد | راه‌حل یا وضعیت | معیار پذیرش |
|---|---|---|
| بازتولید S6a و انتخاب دستی | دستور pixi run s6a با گزینهٔ --c3، ورودی را از برد و intent می‌گیرد. اندازه‌گیری‌های دست‌چین‌شده شاهد امکان‌پذیری‌اند. | برد، intent و تنظیمات یکسان، مجموعهٔ هدف‌ها و مس یکسان بدهند. مس متخصص ورودی S6a نباشد. |
| استفاده از خط پایه با بودجه یا ورودی متفاوت | برای --baseline، هش برد بدون مس و قواعد پروژه، تنظیمات روتر، نسخهٔ KiCad و Java و هش JAR بررسی شوند. | گزارش همسان پذیرفته شود و تغییر برد، قواعد، ابزار یا timeout مقایسه را رد کند. دو طرف C3 مخرج اتصال یکسان داشته باشند. |
| اتصال ویا به pour | KiCad بعد از هر refillِ ناشی از حذف tap و پس از SES، تماس با مس پرشده را بررسی می‌کند. | tap پس از import و refill در شبکهٔ الکتریکی پد و pour موردنظر باشد. tap جداافتاده موفق حساب نشود. |
| برخورد tap چندلایه با مس داخلی | مسیر ویا در کنترل فاصله روی همهٔ لایه‌های مسی بررسی شود. | در آزمون چهارلایه، ترک مانع روی لایهٔ داخلی باعث جابه‌جایی یا رد ویا شود. نمونهٔ واقعی چهارلایه بعد از import و refill پاس شود. |
| افت C3 | مس دیکاپلینگ و تغذیه قبل از جفت‌ها برنامه‌ریزی شود. اثر هر بخش S6a با ablation سنجیده شود. | پوشش S6a حداقل برابر اجرای بدون S6a با تنظیمات همسان باشد، با صفر خطای جدید DRC. |
| فرار پایه‌های تغذیهٔ IC | اتصال به پدهای هم‌نت تأییدشده و tap به pour واقعی پیش از قفل‌کردن جفت‌ها. برای +3.3V بدون pour، مسیر مسی موضعی لازم است. | هر پین تغذیهٔ هدف پس از روت کامل به ریل موردنظر متصل باشد. اتصالات باز و مسیرهای ردشده در گزارش مشخص باشند. |
| جفت‌های باقی‌مانده و تداخل کانال | مسیر خروج پد و محل via به تفکیک جفت اصلاح شوند. ترتیب قطعی در آزمون مشترک سنجیده شود. | هر ۸ جفت StickHub پس از refill متصل باشند، skew حداکثر ۰٫۱۵ mm، تعداد via برابر و در سقف معماری، و DRC بدون خطای جدید باشد. |
| طول /D± | ترتیب پایانه‌ها و محل breakout با مسیر متخصص روی همان برد مقایسه شود. | طول مس هر شاخه، via، skew و DRC گزارش شوند. معیار طول C1 نسبت به متخصص روی مقایسهٔ هم‌شرایط اعمال شود. |
| اعتبارسنجی امپدانس و سایر ماکروها | دادهٔ مرجع Polar و نمونه‌های ساخت، انتقال و readback ماکروهای باقی‌مانده تکمیل شوند. | گیت امپدانس F3 در بازهٔ مرجع پاس شود. ماکروهای بحرانی روی مس واقعی حداکثر ۱۰٪ از معیار متخصص عقب باشند. |
| lint، توابع مشترک و سابقهٔ تصمیم‌ها | منطق مشترک در route/copper.py است. تغییر سازوکار و پارامتر با شاهد در دفتر تصمیم‌ها ثبت شود. | lint و آزمون‌های هدفمند پاس شوند. هر تصمیم الگوریتمی و هر عدد بنچمارک به اجرای قابل‌بازتولید ارجاع داشته باشد. |
| توضیح تغییرات در Git | دلیل و نتیجهٔ آزمون در بدنهٔ commit ثبت شود. | مرورگر commit بتواند اثر تغییر و گیت‌های باز را از خود commit و ارجاع‌های آن تشخیص دهد. |
