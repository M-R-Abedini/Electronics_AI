# یکپارچه‌سازی فضای کاری Electronics AI

تنها ریشهٔ فعال توسعه روی این سیستم **`D:\project\Electronics_AI`** است. `.git`، کد پلاگین، `eda-agent`، اسکیل‌ها، آزمون‌ها و بسته‌بندی مستقیماً زیر همین مسیر قرار دارند.

```text
Electronics_AI/
  .git/                تاریخچهٔ مخزن اصلی
  eda-agent/           موتور طراحی و پل native آلتیوم
  skills/              اسکیل‌های محصول
  scripts/             راه‌اندازی و بسته‌بندی
  tests/               آزمون‌های یکپارچهٔ پلاگین
  analysis/            شواهد خصوصی محلی؛ نادیده‌گرفته‌شده در Git
  tools/               ابزارهای تحلیل و REA؛ نادیده‌گرفته‌شده در Git
```

ادغام در دو مرحله انجام شد: ابتدا مخزن قدیمی به فضای کاری Electronics_AI منتقل شد؛ سپس ساختار موقت تودرتو تخت شد. تاریخچه، تغییرات staged و unstaged، فایل‌های نسخه‌بندی‌نشده و تحلیل‌های قبلی حفظ شدند. قبل از مرحلهٔ نهایی bundle تاریخچه، دو patch و manifest هش تهیه شد؛ هش **۸۱۸ فایل سورس و تغییرات محلی** پس از انتقال یکسان بود. هیچ پروژهٔ سخت‌افزاری دیگری به این مخزن وارد نشد.

مسیر `analysis/former-source-root` فقط بقایای خصوصیِ حفظ‌شده هنگام انتقال است؛ محل توسعه یا نسخهٔ نصب‌شده نیست. خروجی‌های تحلیل قدیمی شواهد تاریخی‌اند و ممکن است نام و مسیر زمان اجرای خود را داشته باشند. این شواهد خصوصی بازنویسی یا به محصول توزیع‌شده اضافه نمی‌شوند.

نام مخزن مقصد `M-R-Abedini/Electronics_AI`، نام محصول Electronics AI، شناسهٔ پلاگین/MCP برابر `mcp-electronics-ai`، marketplace برابر `electronics-ai` و نسخهٔ این تغییرات `0.7.0` است. سازگاری با شناسه‌های قدیمی هدف این نسخه نیست. نوع‌ها و نام‌های واقعی SDK آلتیوم و اعلان‌های حقوقی upstream به نام ساختگی محصول تبدیل نمی‌شوند.

محیط توسعهٔ `.venv` پس از جابه‌جایی باید از ریشهٔ جدید نصب شود. نصب Codex از کش و محیط خصوصی خودش اجرا می‌شود و نباید برای Python یا کد EDA به checkout وابسته بماند. تأیید نصب شامل manifest، هش بسته، قرارداد ابزارها، نسخهٔ wheel و سلامت native است؛ نتایج پذیرش نهایی در [گزارش P0](P0_FOUNDATION_REPORT.fa.md) ثبت می‌شوند.
